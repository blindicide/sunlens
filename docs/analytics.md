# Аналитика

Источник — счётчики байтов Linux TUN из netlink, не замер на удалённом сервере.
`tx_bytes` — upload локального клиента, `rx_bytes` — download. Включаются IP
заголовки, DNS, служебный и направленный через TUN direct-трафик. Физические LAN
bypass пакеты, упавшие до интерфейса пакеты и overhead внешнего VPN протокола
в этих цифрах не учитываются. Учёт по серверу означает **выбранный сервер
сессии**, а не доказательство, что все байты пошли через его прокси.

Помощник опрашивает счётчики примерно каждые 250 мс; GUI сохраняет образцы
не чаще одного раза в секунду в обычном режиме. Первый образец нового TUN
учитывается целиком (у данного интерфейса счётчики начинаются с нуля).
Дальше сохраняется только разность. Старый/повторный образец не прибавляет байты.
Уменьшение хотя бы одного счётчика регистрируется как разрыв: образец становится
новой базой, интервал не оценивается. Новый интерфейс получает новый UUID
сессии; перезапуск ядра, переключение серверов и ядер не переиспользуют базу.
Атрибуция серверу/подписке фиксирована для всей сессии; удаление профиля
не переписывает историю. Источник не обеспечивает точный учёт байтов после
последнего успешного опроса при обрыве, выходе или аварии. Неизмеренный хвост
не экстраполируется. До первого непрерывного интервала скорость недоступна.

Интерфейс подбирает единицы трафика и скорости (Б, КБ, МБ или ГБ, шаг 1024).
В SQLite по-прежнему хранятся точные целочисленные значения в байтах.

Запускаемая вручную TCP-проба без активного SUNLENS TUN измеряет время до
установки TCP-соединения к адресу/порту выбранного сервера (с DNS при необходимости).
Лимит 3 с, трафика приложения, TLS, VPN-авторизации и теста пропускной
способности нет. Отрицательный результат записывается отдельно от измеренных
миллисекунд. Наличие другой системной прокси/VPN этим измерением не проверяется.

Кнопка **Проверить профиль** на главном экране выполняет другой тест. Она
запускает выбранное установленное ядро от пользователя и отправляет один
HTTPS-запрос к `connectivitycheck.gstatic.com/generate_204` только через
выбранный профиль. Ожидается HTTP 204 с действительным TLS-сертификатом,
без перехода по редиректам и без прямого запроса при отказе прокси.
Показанное время включает HTTPS-запрос целиком, но не запуск ядра. Это
не проверка TUN, системных маршрутов, DNS туннеля или пропускной способности.
Тест запускается только вручную при отключённом TUN и не сохраняется в истории.
Если контрольный адрес недоступен, тест не может подтвердить профиль.

SQLite сохраняет временные дельты, события и пробы. По умолчанию история
хранится 30 дней, диапазон 1–3650; очистка происходит при старте, изменении
настройки и периодически во время учёта. Dashboard показывает последние
100 строк и агрегаты по всем сессиям, серверам и группам подписок. Пожизненные
агрегаты сохраняются после очистки истории. Нет destination-истории,
credentials, URL, packet payload или внешней телеметрии в таблицах аналитики.
При удалении всей базы удаляются и профили, и статистика.
